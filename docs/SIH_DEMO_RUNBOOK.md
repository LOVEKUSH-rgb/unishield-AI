# SIH 26145: UniShield AI Demo Runbook

This document provides a step-by-step guide to demonstrating the full end-to-end capabilities of the UniShield AI pipeline (Phases 1 through 11).

## Prerequisites
1. Python 3.10+ installed.
2. Dependencies installed: `python -m pip install -r requirements.txt`

## Step-by-Step Demonstration

### STEP 1: Generate the Golden PCAP
We first need to generate the synthetic network traffic sequence that simulates the attack lifecycle.
```bash
python scripts/generate_demo_pcap.py
```
*This will create `data/samples/demo_scenario.pcap`.*

### STEP 2: Start the Backend API
Start the FastAPI server which runs the Replay Orchestrator and exposes the state.
```bash
python -m src.api.app
```
*The API is now running on `http://127.0.0.1:8000`.*

### STEP 3: Start the SOC Dashboard
In a new terminal window, start the Streamlit UI.
```bash
streamlit run dashboard/app.py
```
*Your browser will automatically open to `http://localhost:8501`.*

### STEP 4: Initialize Live Mode
In the left sidebar of the dashboard, check **Live Sync (Auto-Refresh)**. The dashboard will now poll the backend every 2 seconds.

### STEP 5: Start the Replay
In the left sidebar, click **▶️ Play**. 
The backend is now reading the synthetic PCAP and pumping packets through the `FlowReader`, `FeatureExtractor`, and all 6 detectors.

### STEP 6: Observe Attack Progression
As the PCAP replays, you will see the dashboard populate dynamically:
1. **Normal Traffic**: Flows increment, but no threats are detected.
2. **Reconnaissance**: `Reconnaissance` alerts begin to spike on the Overview Threat panel.
3. **DGA-like DNS**: Shortly after, `DNS_DGA` alerts fire.
4. **C2 Beaconing**: `C2_Beacon` alerts appear.
5. **Encrypted Anomaly**: Anomalous payload timings generate `EncryptedAnomaly` alerts.
6. **Exfiltration**: Finally, massive bursts of traffic trigger `Exfiltration`.

### STEP 7: Observe Cross-Threat Correlation
Notice that a single **Active Correlated Incident** appears in the table. The Correlation Engine correctly grouped all the above behaviors together because they originated from the exact same source IP within a tight time window.

### STEP 8: Observe the Unified Risk Score
Watch the **Risk Level** of the incident transition from `LOW` to `MEDIUM`, to `HIGH`, and finally to `CRITICAL` as corroborating evidence stacks up and the progression matches the recognized attack lifecycle.

### STEP 9: Investigate the Incident
Click on **🔍 Incident Investigation** in the sidebar. Select the `CRITICAL` incident from the dropdown.

### STEP 10: Show the Chronological Timeline
Scroll through the chronological timeline to show how the attack unfolded second by second.

### STEP 11: Show "Why was this flagged?"
Point out the natural language explanation generated by the Risk Engine. Highlight that it relies entirely on mathematically derived `Risk Factors` (shown on the right side) without resorting to black-box ML claims.

### STEP 12: Show Analytics
Navigate to the **📊 Analytics** page. Show the threat distribution charts and identify the top suspicious source (the simulated attacker IP).

### STEP 13: Emphasize the Passive-Only Architecture
Point to the green and blue indicators in the sidebar:
- `Ingest Mode: READ-ONLY`
- `TLS Decryption: DISABLED`
- `Mitigation: DISABLED`

This proves to the judges that the entire detection was performed strictly on passive metadata without violating the core constraints of the problem statement.
