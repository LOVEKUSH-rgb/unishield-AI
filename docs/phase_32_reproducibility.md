# Phase 32: Reproducibility Specification

## Purpose
This document ensures the entire Phase 32 evaluation can be reproduced by any team member with access to the repository, on a system meeting the listed requirements. The benchmark produces deterministic classification results given identical inputs and configuration.

---

## Dataset Files

| File | Purpose | Notes |
|---|---|---|
| `data/samples/demo_flows_expanded.jsonl` | Primary evaluation corpus | 10,000 synthetic flows, deterministically generated |
| `data/samples/phase32_edge_cases.jsonl` | Edge-case regression corpus | Generated by `scripts/generate_edge_cases.py`, committed to repo |

> [!IMPORTANT]
> `data/samples/phase32_edge_cases.jsonl` is committed to the repository. Do **NOT** regenerate it during benchmarking — use the committed file. Run `scripts/generate_edge_cases.py` only if the file is missing.

## Model Artifacts

| Model | Path | Status |
|---|---|---|
| DGA Random Forest | `models/trained/dga_model.pkl` | Optional. Required for ML mode. |
| Encrypted Session XGBoost | `models/trained/encrypted_model.pkl` | Optional. Required for ML mode. |
| Model registry manifest | `models/trained/registry_state.json` | Presence indicates models are loaded |

## Benchmark Commands (Reproducible Execution)

```bash
# Step 1: Generate edge cases (if missing)
python scripts/generate_edge_cases.py

# Step 2: Run the full deterministic benchmark (default / hybrid mode)
python scripts/benchmark_detectors.py \
    --dataset data/samples/demo_flows_expanded.jsonl \
    --output reports/phase32/baseline_metrics.json \
    --mode default

# Step 3: Run statistical-only benchmark
python scripts/benchmark_detectors.py \
    --dataset data/samples/demo_flows_expanded.jsonl \
    --output reports/phase32/baseline_metrics_statistical.json \
    --mode statistical

# Step 4: Run error analysis
python scripts/analyze_detector_errors.py \
    --input reports/phase32/detection_explanations.json \
    --output reports/phase32/error_analysis.json

# Step 5: Run ML vs Statistical comparison
python scripts/compare_detector_modes.py

# Step 6: Run pipeline performance benchmark
python scripts/benchmark_pipeline.py

# Step 7: Run robustness tests
pytest tests/test_phase32_detector_robustness.py -v

# Step 8: Run full regression suite
pytest tests/ -v
```

## Determinism Guarantee

The benchmark is deterministic because:
- `demo_flows_expanded.jsonl` is a committed, static file (no generative randomness at benchmark time).
- Ground truth is assigned via deterministic IP mapping (not random sampling).
- All detectors are stateful (EWMAs, trackers), but they start from a clean state for each benchmark run.
- No random seeds are required — the classification logic is entirely deterministic on repeated runs.

## Known Limitations of Reproducibility

- The EWMA baseline in `DDoSDetector` and `ReconDetector` accumulates over the 10,000-flow stream. If the stream order changes, the EWMA states will differ. The current corpus order is fixed.
- ML model behavior depends on the exact model artifact version (tracked by `registry_state.json` manifest hash).
